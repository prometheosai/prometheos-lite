## Residual risks (explicit, non-pooled)

1. **Exactly-once persistence across crashes is NOT proven.** The #137 recovery path reruns the effect end-to-end; no durable exactly-once key spans the boundary. Campaign coverage is sufficient for slice 1 only.
2. **Dependency-audit supply chain is unverified.** The frontend is scanned for executable markers but `npm ci` against a pinned lockfile was not executed or independently audited in this slice.
3. **Hash-bound builds, not signature verification.** SBOM/Sigstore/provenance attestations are absent; the only pinning is the pinned revision + baseline digest + trusted PostCSS blob.
4. **Allowlist breadth.** `CommandTool::new()` allows `python`, `node`, `npm`, `python3`, `cargo`, `rustc`, etc. That is the default profile for fixture execution; it does not demonstrate a hardened profile for operator-facing execution.
5. **Symlink TOCTOU window.** Symlink checks happen at use time; a symlink created **after** the check can redirect a write. The guard canonicalizes the **parent**, but final-file creation through a freshly swapped symlink has not been closed.
6. **Human approval binding.** The approval receipt is not digest-bound to the specific artifact it authorizes here — assessed separately by the #269/#270/#271 authority-hold work and #155; not in this slice.
7. **Unknown secret classes.** Secrets not in the registered list are not detected at this boundary. Redaction is deterministic but finite.
8. **Command allowlist is basename-only.** A benign-named binary with the same basename as an allowlisted one is accepted (documented semantic, not a bug — but assessors should probe the boundary with argv confusion).

## Independent-assessment requirements (this slice prepares for, not fulfills)

The independent security assessor must, at minimum:

1. Reproduce every SEC-A entry in this matrix from a clean checkout of `main` at the assessor SHA.
2. Compromise one seed boundary (e.g., PathGuard symlink check, ledger precedence, schema tampering) and verify the system still refuses the attack with zero unauthorized effects — not merely "returns an error".
3. Verify no assessment findings were silently dropped or overridden by "it passed tests" (this suite covers ~50 adversarial cases; the full attack surface is larger).
4. Issue a signed assessment report with explicit pass/fail per boundary and residual-risk acceptance — including for items marked "not covered" above.
5. Confirm #297 closure evidence (organization-level provenance + credential-exposure analysis) is linked before closing #138.

## Explicit non-claims

- This matrix prepares the evidence bundle; it does **not** claim the system is "secure" or that an independent assessment has been completed.
- No claim that master is free of #297-class history anywhere other than `main`'s reachable DAG (entire repository may contain the payload on other refs — `git log --all -- frontend/postcss.config.js` is out of scope for this PR).
- No claim that the unchanged `.prometheos` local-state machinery resists tampering (assessed at the journal/lease layer, not here).
